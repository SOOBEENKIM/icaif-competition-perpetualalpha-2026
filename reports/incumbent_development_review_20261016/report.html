우선순위 / 대상현재 근거개발 방향개선 확인 기준
1. 위험 점검과 모델 계산 분리
코드 확인		Runner.cycle이 계좌 조회 → load_signal → 위험 판단 순서다. 자료가 없으면 같은 흐름에서 전체 이력 계산을 한다. 실제 최근 18회 추론의 중앙값은 100.28초, 최댓값 106.96초. 추론·자료 갱신 중 위험 판단은 기다리며 실패하면 해당 주기의 판단을 건너뛴다.자료·신호 생성은 별도 작업으로 수행하고, 계좌 감시와 주문 집행은 독립적으로 계속 동작시킨다. 새 신호가 오래됐으면 신규 위험을 늘리지 않되, 유효한 계좌·시장 자료와 명시된 대체 위험 기준으로 필요한 축소는 가능하게 한다. 주문 서명·전송은 한 곳만 담당한다.모델 계산 지연, 자료 실패, 네트워크 단절을 주입해 위험 점검이 계속되는지 확인. 주문 중복 0, 불명확한 주문 결과는 조회·대조 후에만 다음 주문.
1. 판단·실행 이유 기록
기록 부족 확인		목표 비중·주문·체결은 남지만, 주문 생성 당시 L2·계좌 주문 한도·어떤 제약이 작동했는지와 각 신호의 기여는 충분히 남지 않는다.매 판단에 원래 신호, 각 보정 단계의 비중, 실제 보유, 기준가격, par bid/ask·수량·oracle·mark·펀딩, 비용 추정과 사유 코드를 남긴다. 목표 달성, 버퍼 내 HOLD, 유동성 대기, 가격 초과, 신호 만료, 청산 대기를 구분한다.임의의 매수·HOLD·축소 결정을 저장된 입력만으로 재현하고 숫자를 대조할 수 있어야 한다.
2. 위험 감축 효과 보존
메커니즘 확인, 성과 효과는 가설		최종 보정은 원래 규모의 0.6938789배인 고정 축소다. 중간 normalize_risk는 감축된 목표를 기준 전략 예상 위험의 95%에 맞추도록 최대 2배 확대한다. 단순 입력에서 4% → 위험 필터 2% → 재규격화 3.8%를 확인했다. 실제 현재 손실의 원인이라고 입증한 것은 아니다.‘비교를 위한 위험 수준 맞추기’와 ‘위험 경고에 따른 감축’을 명확히 구분한다. 위험 경고로 줄인 금액은 뒤의 배분 계산이 복원하지 못하는 후보를 하나만 비교한다. 기존 자본·위험 상한을 유지한다.감축이 최종 주문까지 보존되는지 확인. 수익·변동성뿐 아니라 평균 위험·투자 비중도 맞춰 비교해, 단순 소액화 효과와 판단 개선을 분리한다.
3. 현재 가격에서 거래할 가치 판단
코드 확인, 새로운 효용 추정은 미구현		기존 신호는 기준시장 시간봉과 그 시장의 펀딩에서 목표 비중을 만든다. 실행기는 par 가격·깊이로 주문을 제한하지만, 현재 체결가격에서 남은 예상 수익을 별도로 평가하지 않는다. 20% 버퍼와 일부 신호의 고정 38bp 비용 문턱은 현재 par의 거래 비용을 직접 추정하지 않는다.기존 추세·되돌림 신호를 유지하고, 그 신호의 유효기간과 현재 par 가격 괴리·진입/청산 비용·펀딩·불확실성으로 신규 진입, 추가, 유지, 축소를 선택한다. 기다린 뒤에는 남은 수익 여지를 다시 평가한다. 먼저 신호를 수익 단위로 보정할 근거가 있는지 측정해야 한다.체결률 증가가 아닌 비용 차감 후 이익으로 평가. 같은 신호·위험 아래 비교한다. 신규 진입은 왕복 비용, 이미 보유한 포지션은 지금 이후의 증분 비용을 사용해 이미 낸 수수료를 의사결정 비용에 중복 산입하지 않는다.
4. 청산과 보유 상태 관리
코드·미관측 영역		원래 전략에 종료·손절 조건과 계좌 위험 제한은 있다. 다만 전략의 기준시장상 보유 경로와 실제 늦게 체결된 계좌의 경로는 다르다. 아직 실거래 종료 체결을 검증하지 못했다. 앞선 단순 재시도 실험에서는 비용과 잔여 포지션 문제가 남았다.각 실제 보유에 진입 근거·체결가·신호 나이·누적 펀딩·전략 종료 조건을 연결한다. 목표 0과 실제 0을 별도 상태로 두고, 청산 미완료·최소 주문 미만 잔여를 기록한다. 신호 약화·기간 만료에 따른 축소와 계좌 위험 축소를 구분한다. 강한 신호는 유지할 수 있게 하고 임의의 짧은 시간 손절을 덧붙이지 않는다.신호 종료 후 실제 종료까지의 시간·비용·잔여금액, 종료 후 재진입 비용을 측정. 정상·급변·호가 부족 상황의 완전한 진입→보유→청산 과정을 검증한다.
5. 각 모델의 기여와 위험 집중
관측 및 가설		현재 BTC 위험 집중, 고정 혼합·완만한 사이징·HOLD 버퍼가 겹친다. Chronos는 신호에 보정을 주며 최신 예측의 방향이 최종 매수·매도 방향과 항상 같지 않다. 계산한 10/90% 분위수는 현 어댑터에서 유지하지 않고 중간값의 예측 25번째−1번째 차이만 사용한다. regime의 bull_probability는 평활화한 상태 점수이므로 보정된 상승 확률로 해석하면 안 된다.추세 단독, 되돌림 추가, 모델 보정 추가의 기여를 같은 위험에서 따로 분석한다. 현재 공분산 위험 기여를 표시하고 불리한 par 가격 괴리 위험도 별도로 본다. 예측 구간을 사용할 경우 실제 포착률을 먼저 검증한다. 신호가 없는 종목을 억지로 매수해 분산하지 않는다.구성요소 제거 비교에서 비용 차감 후 추가 가치가 남는지 확인. 낮은 회전율·변동성을 단순 현금 보유 효과와 구분한다. 새로운 기간에서 검증하기 전 모델 효과를 확정하지 않는다.

제안하는 에이전트 구조

시장·계좌 기록 → 기존 신호 생성 → 현재 가격의 거래 가치 판단 → 위험 한도·보유 상태 관리 → 단일 주문 집행 → 실제 체결·손익 대조
별도 계좌 감시: 모델 계산과 무관하게 신선한 계좌·시장 자료로 위험 상태를 감시하고, 주문 명령은 같은 단일 집행 경로로 전달.

현재 장점인 주문 전 영속 기록, 단일 실행자, 주문 ID 기반 재시작 대조, 실제 체결·포지션 회계는 유지해야 한다. ‘agent를 여러 개 더 만들기’보다 역할과 상태 전이를 명확히 분리하는 것이 목적이다.

개발 순서와 채택 조건

  1. 먼저 판단 원장과 독립 위험 감시 구조. 기존 신호·주문 규칙을 바꾸지 않고 현재 행동을 설명하고 재현한다. 계산 지연 중에도 감시가 되는지 검증한다.
  2. 첫 전략 후보는 위험 감축 효과를 보존하는 작은 변경. 기존판과 같은 신호, 동일한 자본·위험 한도에서 결과를 비교한다. 더 적게 투자해서 변동성이 줄어든 효과를 따로 밝힌다.
  3. 그다음 현재 가격과 비용을 연결하는 진입·보유·청산 판단. 실제 파생시장 자료로 기대 수익의 보정과 비용 추정이 가능할 때만 도입한다. 초기에는 기존판 옆에서 모의 판단한다.
  4. 마지막으로 모델·전략 혼합 비중 개선. 어떤 구성요소가 유효했는지 확인한 뒤 조정한다. 이번 약 18시간의 손익에 맞춰 여러 임계값을 동시에 고르지 않는다.

기술적 개선은 동일 입력 재현·장애 주입·회계 검증으로 판단한다. 투자 성과 개선은 고정한 후보의 새 기간 결과에서 비용 차감 후 수익, 실제 일별 표준편차, 최대낙폭, 같은 위험 수준 비교, 청산 완료를 함께 확인해야 한다. 현재는 이 설계를 검토한 단계이며 새 후보의 수익 개선을 확인한 단계는 아니다.
