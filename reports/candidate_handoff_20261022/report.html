계좌를 0에서 시작하거나 기존 포지션을 청산하지 않았다. 기존 판단 시각, 주문 식별자와 순번, 최고 평가액·중단 상태, 페어 거래 상태도 보존했다. 이전 전략의 아직 제출되지 않은 목표만 폐기하고 새 목표와 현재 수량의 차이를 계산한다. 인계 장부 수량 오차 0.0, 합산 평가액 오차 1.46e-11 USDP.

구현한 연결

  1. 독립 신호 계산: 고정된 168시간 모델과 기존 위험 보정으로 신호를 생성한다. 모델 재학습은 없다. 계산은 주문 실행 루프와 분리되며, 시간별 새 자료가 있을 때만 수행한다. 기존 페어 신호 생성자는 계속 사용한다.
  2. 기존 계좌 인계: 공개 체결·펀딩을 기존 주문 식별자와 대조해 우리/팀원 장부를 복원한다. 기존 체크포인트의 우리 수량·평균가·수수료·손익과 다르면 활성화가 진행되지 않는다.
  3. 선정 후보의 실제 실행 연결: 후보의 정확한 목표 수량을 유지한 채 기존 페어 상태 기계를 사용한다. 최종 위험 감축, 취득한 실제 수량 유지, 반대 방향 전환 전 청산 규칙을 적용한다.
  4. 같은 종목의 주문: 우리 내부 목표의 차이만 계산하고, 거래소의 합산 순포지션으로 reduce-only와 주문 가능 수량을 결정한다. 거래소 순포지션을 우리 단독 목표로 덮어쓰지 않는다.
  5. 전송·체결: 각 종목 직전에 호가를 새로 조회하고 PAS·USDP·수량 정밀도·OI·실제 증거금·우리 위험 한도를 검사한다. 전송 전에 소유자와 주문 ID를 기록하고 실제 체결 내역만 장부에 반영한다. 응답이 불명확하면 임의 재전송하지 않는다.
  6. 단일 실행자: 기존 봇의 세 잠금 파일을 새 실행자도 모두 사용한다. 현재 기존 봇이 잠금을 보유한 동안 새 실행자가 잠금을 얻지 못하는 것을 실제로 확인했다. 서명자는 이 잠금 획득 이후에만 로드될 수 있다.
  7. 팀원 연결부: 팀원은 자신의 현재 가상 보유량과 목표 수량을 inbox에 제출한다. 같은 실행자가 검사·주문·체결 확인을 담당한다. 만료된 요청, 오래된 보유량, 중복 ID, 부분 체결과 불확실한 응답을 구분한다. 팀원 전략이 독립적으로 거래소 전체 수량을 복구하려고 주문하면 이 보장이 깨지므로 기존 팀원 프로그램을 확인해야 한다.

검증 결과와 남은 조건

테스트 38개 통과. 후보 목표가 실제 실행 어댑터까지 동일하게 전달되는지, 기존 보유와 누적 손익 유지, 롱·숏·전환, 주문 간 호가 갱신, 부분 체결, 팀원 소유 수량 보존, 펀딩 중복 반영 방지, 동일 지갑 잠금, 요청 재전송 차단을 검사했다. 공개 API 검사에서는 BTC·ETH 모두 사전 검사를 통과했다.

남은 조건은 팀원 프로그램의 실제 주문 방식 확인과 연결이다. 같은 종목의 내부 장부 공동 운용에 동의한 것과, 팀원의 현재 프로그램이 그 방식으로 구현된 것은 별개다. 새로운 inbox 인터페이스와 시작 설정 파일은 준비했지만 확인되지 않은 프로그램을 연결 완료로 표시하지 않았다. 팀원 직접 주문을 종료하고 공통 실행기를 사용하도록 바뀐 것을 확인한 뒤 기존 주문 실행자만 중지하고, 신호 생성자는 유지하며 새 실행자를 시작해야 한다.

반대 방향의 내부 수량이 정확히 상쇄되면 거래소의 펀딩 지급액 0만으로 각 전략의 펀딩을 알 수 없다. 실제 관측한 종목별 단위 수량당 정산 정보가 없으면 장부를 임의로 0 처리하지 않고 실행을 멈춘다. 이 예외와 네트워크·미확정 주문 시 중단 경로는 유지한다. 검사 통과가 코드 전체의 무오류나 향후 수익을 보장하지는 않는다.

앞선 48시간 PAS 실험은 체결 가정에 따라 기존 규모보다 PnL·Q가 높았지만, 단순 증액 이상의 예측 이득은 확인하지 못했다. 따라서 이번 판단은 확인된 오류 수정과 합리적인 후보 적용을 위한 실행 준비에 관한 것이며, 독립적인 수익성 우월성 증명은 아니다.
