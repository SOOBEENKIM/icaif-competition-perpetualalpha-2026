SFINX 전략 개선 실험과 교체 판정

작성: 2026-10-25T00:42:18.738200+09:00 · PAS / USDP · 실제 주문 0건 · 운용 전략 변경 없음

조건부 백테스트 PnL 개선 후보는 확보했지만, 교체 검증을 통과한 후보는 없다.

같은 진입가격 제한에서 60분 실행 후보의 전체 PnL은 +39.1875 → +74.3439 USDP, Q는 0.106021 → 0.111069였다. 그러나 동일한 기존 보유분을 인계한 21시간 실험은 +13.5602 → +12.6874 USDP로 낮아졌다. 이 결과와 실제 호가 이력 부족을 숨기고 실전 개선 확정이라고 보고하지 않는다.

평가 범위와 분모

전체: 한국시간 2026-10-19 21:00 → 10-24 21:00(120시간). 인계: 10-24 00:00 → 21:00(21시간). 모든 후보는 우리 몫 50,000 USDP와 움직이지 않는 팀원 몫 50,000으로 평가했다. 실제 팀원의 수익은 섞지 않았다. 표의 수익률 분모는 100,000이며, 우리 몫 기준 수익률은 두 배다. 모든 숫자는 조건부 모의거래이며 실제 계좌 손익이나 공식 순위가 아니다.

일별 표본은 12:00 UTC(한국시간 21:00), 완료 수익률 n=5. σ=표본표준편차×√5, Q=(max(R,0)+0.005)/(|R|+1.5σ+0.05). 따라서 σ를 일별 표준편차 자체로 부르지 않는다. 일별 표준편차는 σ/√5다. J=0 가정 점수는 0.8Q다.

가장 나았던 실행 후보

신호·학습모델·50,000 자본·6시간 판단 주기·총 위험 한도를 유지한다. 미체결 진입 유효시간을 15분에서 60분으로 늘린다. 다만 결정 시점 가격의 ±10bp를 고정해, 재시도 때 가격이 바뀌었다는 이유로 더 불리한 진입을 허용하지 않는다. 1시간 이후에는 실제 남은 우리 수량의 감축만 유지하고, 6시간 신호 만료나 다음 판단 때 교체한다. 숏 전환은 기존 롱 청산을 확인한 뒤 수행한다.

실제 실행과 백테스트의 차이 발견

실행 코드의 기본 신규진입 한도는 시도 시점 mark 가격 ±10bp다. 이전 분봉 실험은 결정가격 ±5%를 허용했다. 동일한 기준이 아니므로 이전 +106.9212 USDP 등의 수치를 실전 교체 근거에서 제외했다. 최종 표는 모든 후보에 결정가격 ±10bp를 동일하게 적용한 재실험이다.

또한 실제 기존 실행자는 매 시도마다 mark를 새로 기준으로 삼는다. 최종 연구용 엔진의 고정 결정가격 제한과도 완전히 같지 않다. 준비한 guarded_portfolio는 이 고정 가격 계약을 코드에 명시했지만, 기존 실행자의 역사적 mark·호가·대기열을 복원한 것은 아니다. 이전 unsigned gateway preflight는 이 상위 가격 필터를 거치지 않았으므로 전체 실행 통과 증거로 취급하지 않았다.

실제 저장 로그에서 가격 제한 차단 8건을 확인했다. 이 중 10월 24일 15시 라운드 SP500 숏 차단이 7건이다. 당시 호가가 저장되어 있지 않아 이것이 잘못된 차단인지, 정상적인 비용 보호인지는 확정할 수 없다. 가격 제한을 무조건 넓히는 수정은 하지 않았다.

왜 PnL이 작았는가

  1. 현재는 BTC·ETH 전용/롱 전용이 아니다. 우리 장부는 BTC·BRENT 롱, ETH·HYPE·EWY·EWJ·GOLD·USDEUR·USDJPY 숏이며 SP500은 0이다. 현재 미진입 이유와 종목 미평가를 구분해야 한다.
  2. 고정된 외부시장 추세·7일 되돌림에 Chronos와 국면 위험 보정이 적용되고, 실제 PAS 진입에는 3h 또는 24h 되돌림 조건이 추가된다. 당시 8개 종목에 위험 감축 표시가 있어 목표를 늘리기 어렵다.
  3. 추가 배분 모델은 기존 방향 목표가 0이고 위험 보호 대상이 아닌 슬롯을 주로 사용한다. 약한 예측과 비용 문턱 때문에 ‘한도가 남음’이 자동 투자로 이어지지 않는다. 작은 포지션을 무조건 채우면 위험 감축을 다시 확대할 수 있다.
  4. 6시간 판단·15분 실행창, 얇은 체결량, 최소주문금액, 가격 제한과 API 지연이 실제 수량을 줄인다. 반대로 주문창만 늘렸을 때의 추가 거래가 항상 돈을 벌지는 않았다.
  5. 보존된 페어 전문 모듈은 BTC/ETH·BTC/HYPE 두 관계이며 평가 기간의 진입 게이트는 모두 0이었다. 이번 개선을 45개 페어의 예측 개선이라고 포장하지 않는다.
  6. EWJ 기준시장 자료의 한 시간 누락이 전체 신호 갱신을 막은 기록이 있다. 실제 미발행 시간은 재현에서도 건너뛰었다. 누락 봉을 지어내지 않았고, 뒤늦게 API 자료가 복구되며 실제 갱신도 회복했다.

전체 PnL에는 미실현손익도 포함된다. 표시한 레버리지는 설정 레버리지가 아니라 gross notional/equity다. 설정 20배와 실제 20배 노출은 다르다. 우리 팀 전체 PnL +231.79 중 당시 우리 몫은 +69.07, 팀원 몫 +162.72였다. 우리 보유 명목금액 9,981.62는 우리 50,000의 약 19.96%다.

확보한 초기 지급 지갑에서 우리를 제외한 46개, PAS 체결 28,681건을 모았다. 현재 승자만 고르지 않고, 모든 지갑의 동일비중 방향과 당시 전일 가격손익(수수료 차감, 펀딩 제외)으로 선택한 양수 상위 25% 집단을 각각 재현했다. 관측에 120초 지연을 주고 같은 자본·위험·체결 제한을 적용했으나 두 방식 모두 개선하지 못했다. 타 지갑의 좋은 현재 성과만 보고 과거부터 따라샀다고 가정하지 않았다. 동일 밀리초 체결 순서는 startPosition→endPosition 연결로 검증했다.

검증과 남은 한계

  • 119개 실제 발행 시각과 원본 입력 접두 구간을 확인했다. 미발행 10월 24일 16시 자료는 소급 발행하지 않았다.
  • 저장 당시 예측과 최신 일괄 추론의 소수점 차이는 최대 4.768371582e-07. 당시 예측으로 치환했을 때 모든 목표 비중·위험 보호 마스크가 정확히 같았다. 미래 정답으로 재학습하지 않았다.
  • 최종 동일 조건 비교 39회 모두 시각 순서·장부 보존 검사 통과, 강제 위험 한도 초과 0. 비영 펀딩은 실제 공개 지급액에서 복원했다. 지갑 추종 두 기본 시나리오에는 대체 계산 카운터가 각각 10·5회 있지만, 전부 공식 펀딩률 0인 USDJPY 관측임을 따로 확인했다. 어떤 가격을 곱해도 지급액이 0이므로 손익 영향은 없다.
  • 41개 표적 검사 통과. 실제 실행 경로에서 가격 제한, 감소 우선, 중복 방지, 미확정 체결 차단, 기존 보유 인계, 결정 시점 가격 고정, 미래 가격을 바꿔도 과거 신호가 바뀌지 않는지 검사했다.
  • 기본 비용: 편도 9bp 수수료+10bp 불리한 체결, 관측 거래량 1%. 불리한 조건: 12bp+20bp, 거래량 0.25%, 수취 펀딩 절반. 추가로 수취 펀딩 0도 시험했다. 대기열·미래 호가 수량을 안다고 가정하지 않는다.
  • 분봉 고가 매수·저가 매도+불리한 체결을 사용하고, 결정 뒤 완전히 끝난 다음 봉부터만 체결 가능하다. 이는 조건부 보수 모델이지 실제 호가 재현은 아니다. 최종 평가가격에도 오래 거래되지 않은 종목이 있어 공식 mark 기반 점수와 다를 수 있다.
  • 119시간 신호를 갖고 여러 후보를 비교한 기록 자체가 선택 편향을 만든다. 미사용 테스트라는 이름을 붙이지 않았다. 21시간은 새 완료 일별수익률 두 개를 만들지 못하므로 독립적인 새 기간 변동성·Q를 주장하지 않는다.

코드와 재현 자료

연구 코드는 프로젝트의 execution_revision_20261024/, 원본·결과는 reports/execution_revision_20261024/에 있다. 실제 운용 candidate_handoff 및 실행 설정은 변경하지 않았다.

  • 최종 동일조건 비교 CSV · 검증 결과 · 테스트 출력
  • 60분 후보 상세 · 지갑 추종 상세 · PAS 추세 상세 · 펀딩 상세
  • 교체 보류 근거와 최종 코드 해시 · 실제 실행 로그 집계 · 발행 당시 예측 대조
  • 실행 예: .venv/bin/python -m unittest execution_revision_20261024.test_guarded_portfolio execution_revision_20261024.test_validation execution_revision_20261024.test_portfolio execution_revision_20261024.test_cashflow_overlay execution_revision_20261024.test_peer_prepare -q

실험은 원본·결과 덮어쓰기를 막도록 설계했다. 완료한 run 명령을 그대로 재실행하면 중단하는 것이 정상이다. 복제된 연구 디렉터리와 별도 출력 경로에서 재현해야 한다. 오래된 인계 checkpoint를 실전에 복원하면 안 된다. 인계는 항상 당시 최신 장부로 다시 검증해야 한다.
