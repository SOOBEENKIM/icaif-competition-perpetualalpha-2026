실시간 연결 점검

현재 기준시장 입력으로 BTC–ETH·BTC–HYPE의 선정 decision gate 판단을 생성했다. PAS 10종목의 실제 공개 호가와 평가가격도 읽었다. 무서명 실행 점검에서 USDP 미지급·포지션 0·주문 0을 확인했다. 신호 작업자와 주문 실행자를 분리해 모델 계산이 계좌 감시 흐름을 직접 막지 않게 했다.

실운용 시각은 실제 수신 시각을 유지한다. 15분 판단 경계의 첫 30초 중 한 번만 새 페어를 평가하며, 다른 종목의 호가 부재는 신선한 평가가격을 이용한 계좌 평가를 막지 않는다. 해당 종목의 거래 가능 호가가 없으면 주문하지 않는다. 이 두 가지는 실시간 입력 연결을 위한 보완이며 가격 예측·진입 경제성·보유·청산 규칙은 유지했다.

실거래 활성화와 구분

본대회 전환 코드와 사전 점검은 완료했으며, 자동매매 서비스는 아직 시작하지 않았다. 활성화 때 기존 연습 주문 프로세스를 종료하고 준비한 신호 작업자·PAS 실행자를 실행해야 한다. 실행자는 기존 연습 봇과 같은 지갑 잠금을 함께 잡으며, USDP 실제 지급과 기존 상태 대조를 마친 뒤에만 키를 읽고 주문할 수 있다.

시작 시 100,000 USDP의 실제 지급·계좌 상태·API 승인·메타데이터를 다시 확인해야 한다. 새로운 주문이 불명확하면 재전송하지 않고 cloid와 실제 체결로 대조한다. 승인된 지갑이 있다는 사실만으로 주최 측의 최종 참가 자격을 확정하지 않는다.

실시간 기본 전략의 새 시간봉 추론은 원래 프로젝트의 practice_live와 기존 모델 캐시에 의존한다. 패키지의 보관된 기준 전략 목표만으로 새 미래 시간봉을 계산하는 것은 아니다. 배포 시 --workspace는 원래 프로젝트 디렉터리를 가리켜야 하며, 같은 Python 환경의 의존성과 모델 캐시를 유지해야 한다. 재시작 시 미확인 주문이나 수량·현금 불일치가 있으면 재전송을 멈추고 실제 주문·체결을 대조해야 한다.

추후 활성화 명령 — 이번 점검에서 실행하지 않음

원래 프로젝트 작업 디렉터리에서 서로 독립된 두 장기 실행 프로세스로 실행한다. 첫 명령은 신호만 생성하고, 두 번째 명령의 --execute가 실제 PAS 주문을 활성화한다. 프로세스 감독·알림 설정은 실제 활성화 단계에서 설치한다. STOP 파일이 남아 있으면 시작하지 않는다.

python -m scored_phase.producer
python -m scored_phase.runner --execute
