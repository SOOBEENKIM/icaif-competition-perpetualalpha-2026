# Offline Replay Lab

팀 자금과 독립된 가상 계좌에서 모델 학습, agent 결정, 주문·체결, 손익 계산을
확인하는 로컬 연구 도구입니다. 릿지는 Python 3.11 표준 라이브러리만 사용하며,
XGBoost는 별도의 CPU 연구 의존성을 사용합니다.
Hyperliquid의 지갑·거래소 API, 기존 `bot` 패키지, 계정 설정이나 API 키를 읽지 않습니다.

## 실행

프로젝트 루트에서:

```bash
.venv/bin/python -m replay_lab
```

브라우저: <http://127.0.0.1:8765>. 다른 포트는 `--port 8766`처럼 지정합니다.
종료는 터미널에서 `Ctrl+C`. 서버는 루프백 주소에만 바인딩하고 명시한 화면/API 경로만
응답하므로 프로젝트 폴더를 웹 디렉터리로 노출하지 않습니다.

### 원격 워크스테이션에서 실행할 때

서버와 브라우저가 서로 다른 컴퓨터에 있으면 `127.0.0.1` 주소만으로는 연결되지 않습니다.
**브라우저가 실행되는 PC/노트북 자체의 터미널**에서 SSH 터널을 유지합니다.

```bash
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:8765:127.0.0.1:8765 finx_sbk@WORKSTATION_HOST
```

`WORKSTATION_HOST`를 기존 SSH 주소로 바꾸거나, `finx_sbk@WORKSTATION_HOST` 전체를
기존 SSH 별칭으로 바꿉니다. 별도 SSH 포트를 쓰는 경우 기존 `-p` 옵션도 유지합니다.
연결 후 PC/노트북의 <http://127.0.0.1:8765>가 워크스테이션의 같은 포트로 전달됩니다.
터널 연결 후 별도 출력 없이 기다리는 상태는 정상입니다. 두 컴퓨터의 포트 번호를
모두 동일하게 사용하면 서버의 Host/Origin 검사에도 맞습니다.

접속 문제를 구분하는 확인 명령은 **워크스테이션**에서 실행합니다.

```bash
curl --noproxy '*' -sS -o /dev/null -w '%{http_code}' http://127.0.0.1:8765/
```

`200`이 출력되면 서버가 화면을 정상 응답한 것입니다.
워크스테이션에서는 응답하지만 PC/노트북에서 연결 거부라면 터널과 실행 위치를 확인합니다.
워크스테이션 자체에서도 연결 거부라면 먼저 서버 실행 터미널을 확인합니다.

```bash
# 서버 없이 학습·백테스트·HTML/JSON 저장
.venv/bin/python -m replay_lab --no-serve

# 지정가 진입 / 12시간 예측 실험
.venv/bin/python -m replay_lab --order-type limit --horizon 12
```

`output/latest.html`은 인터넷과 서버 없이 브라우저에서 열어 재생할 수 있습니다.
설정 변경 후 재실행은 로컬 서버에서 지원합니다. `output/latest.json`에 입력 CSV의
SHA256, 설정, 학습 모델 파라미터, 예측 평가, 모든 판단·주문·체결·계좌 스냅샷을 저장합니다.
재실행은 latest 파일을 교체하지만, **각 결과는 별도로 자동 보관**됩니다.
지속적인 실시간 모의매매나 실시간 주문 봇은 이 도구의 기능이 아닙니다.

## 실험별 저장과 고정 URL

- `http://127.0.0.1:8765/`: 가장 최근 실험을 보고 새 실험을 실행하는 화면.
- `http://127.0.0.1:8765/runs/`: 실험 보관함. 기간·비용·모델·성과를 나란히 확인합니다.
- `http://127.0.0.1:8765/runs/<실험 ID>/`: 특정 결과의 고정 URL.
- `output/runs/<실험 ID>/index.html`: 해당 결과의 서버 없는 재생 파일.
- 같은 폴더의 `report.json`: 모델 파라미터, 데이터 해시, 설정, 전체 거래·계좌 기록.
- `source/`: 보관 시점의 모델·agent·화면 관련 소스와 SHA256. 지갑/키/계정 설정은 포함하지 않습니다.

실험 ID는 모델 식별자·예측 시간·결과 해시로 정합니다. 모델·설정·데이터·결과가 같으면
같은 URL을 재사용하고 기존 보관본을 덮어쓰지 않습니다. 결과가 달라지면 새 URL이 생깁니다.
보관본에서는 재생·조회·JSON 다운로드만 가능하며 재학습은 실행하지 않습니다.
새 실험은 상단 `실험실로`에서 시작합니다. 구현된 모델은 릿지 회귀, XGBoost, QuantDiffusion입니다.
설정에서 모델을 선택하거나 CLI의 `--model ridge`, `--model xgboost`, `--model quantdiffusion`을 사용합니다.

이미 저장된 결과와 보관함만 빠르게 열려면:

```bash
.venv/bin/python -m replay_lab --from-latest
```

이 명령은 모델을 재학습하지 않습니다. URL은 서버와 SSH 터널이 켜져 있을 때 접근할 수 있고,
보관 파일은 서버를 꺼도 워크스테이션에 남습니다.

## 화면에서 확인하는 순서

1. 첫 화면은 전체 테스트 결과입니다. `처음부터 재생` 또는 시간 슬라이더로 이동합니다.
2. `다음 체결`은 다음 실제 시뮬레이션 체결 봉과 종목으로 이동합니다.
3. 왼쪽 종목을 선택하면 캔들, 포지션, 예측·이유가 함께 바뀝니다.
4. 체결·주문·판단 기록의 행을 누르면 해당 시점으로 이동합니다.
5. `대회 평가`는 현재 시점까지의 계좌 지표입니다. `모델 검증`은 전체 테스트 기간의
   사후 평가이며 재생 시점과 무관합니다. 그 평가값은 agent 입력에 쓰이지 않습니다.

## 모델과 시간 분리

- 입력: 10종목 공통 시간축의 시간봉. 첫 48시간은 특징 계산 준비 기간입니다.
- Train: 2026-03-18 이후 공통 기록 ~ 06-30.
- Validation: 07-01 ~ 08-14. Test: 08-15 ~ 10-05 16:00 UTC.
- 특징 11개: 1/3/6/12/24/48시간 로그수익률, 24시간 수익률 변동성, 현재 봉 가격범위,
  평균 대비 로그 거래량, UTC 시간의 sin/cos.
- 목표: 봉 마감 시점부터 H시간 뒤까지의 로그수익률. 기본 H=4.
- 종목별 릿지 회귀. 특징 평균·표준편차는 Train에서만 계산합니다.
- α 후보 0.001/0.01/0.1/1.0 중 Validation MAE가 가장 작은 값을 선택합니다.
  Test에서는 모델을 고정하며, Validation으로 재학습하지 않습니다.
- 미래 정답의 관측 시점이 다음 구간으로 넘어가는 학습/검증 사례는 제거합니다.
- MAE/RMSE/방향 정확도, 항상 0을 예측하는 모델의 MAE를 비교합니다.
  서로 중첩되는 H시간 정답은 독립 관측이 아니므로 통계적 유의성을 주장하지 않습니다.

이 모델은 연구용 baseline입니다. 우수한 투자 전략이나 diffusion 모델로 표시하지 않습니다.
새 모델 연결 지점은 `model.py`의 `train_models` 반환 계약입니다.
종목별 전체 시간축의 **각 봉 마감에 이용 가능한 예측**과 설명, 학습 검증 메타데이터를
반환하면 동일한 `engine.simulate`와 화면을 사용할 수 있습니다.

### QuantDiffusion 후속 실험

```bash
.venv/bin/python -m pip install -r requirements-diffusion.txt
.venv/bin/python -m replay_lab.diffusion_experiment
.venv/bin/python -m replay_lab --from-latest
```

기존 `/home/ssd-990/soobeenkim/quantdiffusion`의 Diffusion-TS 모델 파일 세 개를
이 프로젝트의 `quantdiffusion_core/`에 복사하고 패키지 import만 변경했습니다.
원본 프로젝트는 수정하지 않았습니다. 원본 파일 해시와 출처는 `NOTICE.json`,
공식 MIT 라이선스는 같은 폴더의 `LICENSE`에 있습니다.

- 입력: 48시간 × 10종목의 원시 시간별 로그수익률. 릿지/XGBoost의 종목별 특징 11개와
  표현이 다르며, 종목 간 정보를 함께 사용합니다. 완전히 같은 특징의 모델 교체 실험은 아닙니다.
- 학습: 48+H시간 구간 전체를 복원하는 기존 Diffusion-TS 학습 목적. encoder 1층,
  decoder 2층, 폭 32, 확산 100단계. 원래 지수 데이터의 가중치를 가져오지 않고 다시 학습합니다.
- 정규화: 학습 창에 실제 포함된 고유 시간별 수익률의 평균·표준편차만 사용합니다.
  기존 데이터 로더의 `fit_scope=all`을 사용하지 않습니다. 경계를 넘는 정답 창은 제외합니다.
- 최대 40 epoch, 매 10회마다 사전에 정한 검증 구간의 128시점(고정 8시간 블록)을 평가합니다.
  종목 평균 예측 MAE로 체크포인트를 선택하고 검증 전체 및 테스트 성능을 후속 계산합니다.
- 예측: 과거 48시간만 공개하고 미래 H시간의 입력은 0으로 가립니다. 기존 conditional infill,
  10 sampling step, 시점별 8개 경로를 생성합니다. 각 경로의 H시간 수익률을 합친 후 평균을
  기존 agent에 전달합니다. 매매 임계값·노출·체결·비용·청산 규칙은 변경하지 않습니다.
- 생성 경로의 10/90 분위와 양수 경로 비율은 탐색용 표시입니다. 8개 경로만으로 보정된
  확률이나 신뢰구간을 주장하지 않으며, 이번 agent는 이 분포 값을 판단에 사용하지 않습니다.
- 난수는 고정 시각 블록별로 관리합니다. 미래 값이 조건 입력이나 정규화·모델 선택에
  들어가지 않는지, NPZ 가중치 복원 후 같은 예측을 내는지 검사합니다.

설계는 `diffusion_protocol.json`, 중간 학습 기록과 선택 모델은 `output/diffusion_checkpoints/`,
완료된 기간별 보고서는 `output/diffusion_drafts/`에 있습니다. 중간 체크포인트는 자동 재개용
optimizer 저장이 아니며, 완료 보고서가 있는 기간은 재사용합니다. UI를 나중에 출판하려면
`--train-only`, 이미 완료한 보고서를 재학습 없이 출판하려면 `--publish-only`를 사용합니다.
NPZ는 pickle 없이 저장하며, 실험 보관함에 가중치·정규화·프로토콜·출처·소스 해시를 함께 보관합니다.

세 모델 결과는 `/comparison/`, 기존 두 모델 결과는 `/comparison/ridge-xgboost/`에서 볼 수 있습니다.
원본 Ridge/XGBoost 보고서를 덮어쓰지 않으며 모델별·기간별 고유 URL을 유지합니다.

첫 실행 결과 (비용 차감 후 수익률, UTC 경계):

| 평가 구간 | Ridge | XGBoost | QuantDiffusion |
|---|---:|---:|---:|
| 2026-06-15 00:00 → 07-15 00:00 | −0.082% | −0.998% | −2.353% |
| 2026-07-15 00:00 → 08-15 00:00 | +0.181% | +0.002% | −1.168% |
| 2026-08-15 00:00 → 10-05 16:00 | −0.374% | −0.229% | −1.093% |

기존 평가 기간에서 QuantDiffusion은 체결 167건, 수수료 3,827.76, 순손익 −10,930.94 USDPR,
거래일 15일입니다. 세 모델 모두 이 기간의 종목 평균 MAE가 항상 0을 예측하는 기준보다 큽니다.
이번 설정의 Diffusion은 개선을 보이지 않았으며, 다른 Diffusion 구성 전체에 대한 결론은 아닙니다.
향후 모델/agent 개선에서도 이 결과를 본 기간은 독립 최종 시험으로 취급하지 않습니다.

### 공통 매매 규칙

- 완성된 시간봉으로 예측한 단순 수익률이 `2 × (taker + slippage) + buffer`를 넘으면
  롱/숏 진입을 결정합니다. 기본 buffer=2 bp, taker=9 bp, slippage=5 bp입니다.
- 종목당 목표 노출 기본 5%, 전체 신규 진입 노출 상한은 평가자산의 50%입니다.
  매 거래마다 목표 수량을 계산하며 포지션을 보유하는 동안 증액하지 않습니다.
- 반대 예측, 최대 보유 8시간, 봉 마감 가격으로 손절 2% / 익절 4%면
  reduce-only 시장가 정리를 **다음 봉**에 시도합니다. 이는 실제 장중 TP/SL 주문이 아닙니다.
- 신규 주문은 다음 봉부터 활성화합니다. 시장가는 다음 봉 시가 ± 가정 슬리피지.
- 지정가가 다음 봉 시가에서 시장성이 있으면 limit 이내에서 taker 체결을 가정합니다.
  그 외에는 봉의 저가/고가가 limit을 엄격히 통과할 때 maker 체결 후보입니다.
  단순 touch는 체결하지 않습니다. 실제 대기열·다중 호가 단계는 알 수 없습니다.
- 체결 수량은 `min(직전 봉 거래량, 현재 봉 거래량) × 참여율` 상한을 적용합니다.
  현재 봉 전체 거래량 사용은 **사후 체결 근사**이며 모델이나 주문 수량 결정에는 미리 들어가지 않습니다.
  실제 거래소의 시가 순간 유동성을 재현한다는 의미가 아닙니다.
- 부분 체결 지원. 시장가 잔량은 즉시 취소, 지정가는 기본 3시간 후 미체결 잔량 취소.
  0거래량/0체결 봉은 체결하지 않습니다. 종목별 수량 단위와 신규 주문 $10 최소값을 적용합니다.
  수량 단위는 저장된 엔진 설정이며, 실제 런타임 metadata를 조회하지 않습니다.
  GOLD는 기존 0.001 단위를 유지합니다. 현재 가이드의 0.0001과 다른 이 항목은
  모델 비교 조건을 바꾸지 않기 위해 두 모델 모두 동일하게 적용했습니다.
- 매 체결 notional에 maker/taker 수수료를 차감합니다. 양수 펀딩 가정은 롱 지급·숏 수취입니다.
  시간봉 시작에 기존 포지션에 적용하며, open을 오라클 대용으로 사용합니다.
- `equity = initial + realized gross PnL − fees + net funding + unrealized PnL`.
  선물 진입 시 notional 전체를 현금에서 차감하는 현물 계좌 방식은 사용하지 않습니다.
- 마지막 포지션은 강제 매도하지 않고 마지막 종가로 평가합니다. 미체결 주문은 취소합니다.
- 체결량 상한 때문에 정리가 지연될 수 있습니다. 손절 조건은 손실 상한을 보장하지 않습니다.

## 공식 기준과 재현의 한계

[About](https://perpetual-alpha26.github.io/about),
[Participant Guide](https://perpetual-alpha26.github.io/docs/),
[Hyperliquid 주문 종류](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/order-types)를
2026-10-06에 확인한 기준입니다.

- 계좌 순수익률, 일별 수익률 표준편차의 음수, 10일 거래 여부와 누적 거래대금을 표시합니다.
- 일별 수익률은 UTC 완결 일자 기준의 단순 수익률, 표본 표준편차(ddof=1)입니다.
  마지막 미완결 날짜는 변동성에서 제외합니다. 공식 집계 시각·세부 통계 규약은 미확정입니다.
- 다른 팀 결과가 없으므로 min–max 정규화 불가. 심사위원 점수와 현재 확정 합산 가중치가
  없으므로 최종 점수·등수를 만들지 않습니다. 최소 거래대금 숫자도 확인되지 않았습니다.
- 원본은 mainnet 참조 trade OHLCV이며 par 오라클/mark/체결 기록과 다릅니다.
  역사적 오라클 없이 종가 평가하므로 공식 종료평가와 완전히 같지 않습니다.
- 실제 펀딩 이력 없이 기본값 0을 가정합니다. 0은 펀딩이 실제로 무료였다는 의미가 아닙니다.
- 과거 호가·매수매도 스프레드·가격 충격·큐 우선순위·정확한 장중 체결 경로는 재현하지 않습니다.
- 레버리지 증폭·유지증거금·강제청산·실제 OI cap·API 지연·장애는 구현 범위에 포함되지 않습니다.
  화면의 노출 한도는 거래소의 사용 가능 증거금과 다릅니다.
- MDD는 보조 지표이며 공개 공식 배점의 별도 항목으로 표시하지 않습니다.
- 테스트 구간을 보며 설정을 바꾸면 그 구간은 더 이상 독립적인 최종 검증이 아닙니다.

## 거래·포트폴리오 UI (2026-10-06 보완)

- `/#trade`: 캔들·거래량, 진입/청산 가격 표시, 평균 진입선, 판단→체결→비용→예측 결과.
  시간 표시는 KST 기본이며 UTC로 전환할 수 있습니다. 집계 일자는 기존 UTC 기준입니다.
- `/#portfolio`: 24H/7D/30D/전체 기간의 평가자산·PNL·수익률 그래프, 최근 14일 거래대금,
  비용 및 보유분, 거래 기록과 하단 비교 리더보드.
- `/#leaderboard`: 기본값은 데이터·기간·설정이 같은 저장 모델 간 비교입니다. 모든 행은
  현재 재생 시점까지만 사용합니다. 순수익률/손익/변동성/최대 낙폭/수수료/거래일을 표시하고
  모델 이름을 누르면 해당 고정 보고서의 현재 UI로 이동합니다.
- `다른 트레이더 포함` 선택 시 사용자가 제공한 2026-10-06 이미지의 다른 트레이더 9명을 고정한 참고 비교.
  이미지의 본인 지갑 행(16,364위)은 모델 행과 다른 계좌 기록이므로 비교 대상에서 제외합니다.
  상대 PNL/ROI/거래대금은 이미지의 30D 표시값을 그대로 사용합니다. 내 결과는 현재 커서
  직전 30일로 계산하며, 부족하면 관측 기간만 표시합니다. 서로 다른 기간·자금·표시 통화의
  단순 비교이고 전체 거래소나 대회의 공식 순위가 아닙니다. 검색 전 전체 표시 대상 중 순위를 유지합니다.
- 순위는 선택 지표에서 더 좋은 값의 개수 + 1이며, 동률은 같은 순위를 부여합니다.
  변동성은 낮은 순서, 나머지는 큰 순서입니다. 이미지에 없는 변동성·낙폭으로 상대 순위를 만들지 않습니다.
- 내 기간 PNL = 종료 equity − 시작 equity. 초기 자금 이후 입출금 없음.
  비교 ROI = PNL / max(100, 시작 equity), 최대 순입금액은 0.
  거래대금·수수료·펀딩은 같은 구간 경계에서 누적값의 차이를 사용합니다.
- 거래소의 예측시장(Outcomes)과 우리 모델 예측을 구분합니다. TWAP·체이스·스케일·
  추적 손절·조건부 주문은 현재 엔진에서 미지원으로 안내합니다. 스왑은 이 선물 실험의 대상이 아닙니다.
- 실제 mark/oracle/OI·증거금·청산가·ROE는 값이 없거나 미구현이면 `—`로 표시합니다.
  전체 명목 노출/equity만 `실효 노출`로 계산하며 거래소 설정 레버리지와 구분합니다.
- 새 화면은 동일한 보고서를 읽습니다. 기존 `runs/<id>/index.html`과 `report.json`은 보존합니다.
  `/runs/<id>/view/`는 고정 보고서를 현재 UI로 보여주는 조회 전용 주소입니다.
  이 주소의 화면은 향후 UI 수정에 따라 바뀌지만 원본 수치·설정은 바뀌지 않습니다.

## Diffolio / Chronos-2 / 불확실성 매매 실험 (2026-10-07)

`/comparison/`는 같은 기본 agent를 사용한 예측 모델 5개를, `/strategy-comparison/`는 같은 Diffolio 예측에 매매 규칙만 바꾼 2개 실험을 비교합니다. 각 거래 화면의 리더보드는 같은 평가 조건의 6개 모델·전략을 보여줍니다. 이미지 참고를 선택하면 기존 트레이더 9명과 합쳐 15개 항목이며 실제 대회 등수가 아닙니다.

| 실험 | 6/15–7/15 UTC | 7/15–8/15 UTC | 8/15–10/5 16:00 UTC |
|---|---:|---:|---:|
| Ridge regression | -0.082002% | +0.181338% | -0.373525% |
| XGBoost | -0.998177% | +0.002270% | -0.228586% |
| QuantDiffusion | -2.352874% | -1.167975% | -1.093094% |
| Diffolio-adapted | -4.237849% | -2.158102% | -2.250610% |
| Chronos-2 | -1.496537% | -1.783521% | -3.009540% |
| Diffolio + 위험필터 | -2.330274% | -1.303512% | -1.951573% |

모든 수치는 비용 차감 후 계좌 수익률입니다. 세 구간은 서로 별개로 100만 가상 USDPR에서 시작하며 연속 성과가 아닙니다. 세 평가 구간의 결과를 이미 확인한 탐색적 실험입니다.

- Diffolio-adapted는 [논문 v2](https://arxiv.org/abs/2511.07014v2)의 조건부 노이즈 예측, 종목별 cross-attention, 시장 self-attention, 상관행렬 행별 cosine 정규화를 독립 구현했습니다. 일봉 산업 포트폴리오 대신 시간봉 10종목, 48시간 입력, 4시간 로그수익률 벡터를 사용합니다.
- 종목 입력은 시간별 수익률·거래량·봉 범위, 공통 입력은 UTC 시간 sin/cos입니다. 논문의 거시 변수, Ledoit–Wolf 축소 대신 고정 50% 공분산 축소를 사용합니다. 폭 32, 80 epoch, 64개 시나리오, DDIM 20단계, 복원 표준값 ±6 제한은 축소 적용 실험의 설정이며 논문의 구현·성과를 재현한 것이 아닙니다.
- Diffolio 입력/목표 정규화와 공분산 기준은 학습 데이터에만 적합합니다. 20/40/60/80 epoch 중 사전에 지정한 검증 128시점의 MAE로 선택합니다. 테스트 수익률로 선택하지 않습니다. 전체 검증 MAE는 선택에 사용한 부분 검증 MAE와 구분합니다.
- [Chronos-2](https://arxiv.org/abs/2510.15821)는 공식 공개 가중치 `95a9710e2596287d08352589f42634fa5abdf0a7` (2025-10-30)을 고정했습니다. 로컬 자료는 2026년부터이므로 공개 시점이 앞섭니다. 다만 원 사전학습 자료 전체를 독립 감사하지 않았습니다. 로컬 재학습·튜닝 없이 48개 로그 종가에서 4번째 미래 시점의 중앙값을 사용합니다. 시점마다 10종목을 한 task로 묶고 `cross_learning=False`로 다른 시점 사이 정보 공유를 막았습니다. 서로 다른 원자료 표현/사전학습 이력 때문에 순수 구조 차이만의 비교는 아닙니다.
- 위험필터는 Diffolio 저장 가중치·예측값을 재사용합니다. 원래 평균 예측 신호에 더해 비용을 넘는 표본 평균 이익, 이익 표본 비율 60%를 요구하고, 약 하위 10% 표본의 평균 손실에 대한 자산 위험 예산 0.1%로 진입 수량을 줄입니다. 종목당 5%, 전체 명목 노출 50% 한도와 기존 청산 규칙은 유지합니다. 실제 최대 손실을 보장하지 않으며 논문의 MVP/GOP 최적화가 아닙니다.
- 분포의 실제 포함률·CRPS와 예측 MAE, 항상 0 예측 기준, 수익률·낙폭·비용을 함께 기록합니다. 위험필터의 수량 변화로 이후 포지션 상태가 달라지므로 전체 체결 수가 반드시 감소하지는 않습니다.
- 가중치·설정·평가 구간·거래 이력은 각각 별도 URL에 보관됩니다. Diffolio NPZ는 pickle 없이 저장하고, 공동 시나리오 NPZ는 float32로 보관합니다. 위험필터가 사용하는 점 예측은 원본과 완전히 동일하며 표본 분포의 저장 정밀도만 float32입니다. Chronos 대형 가중치는 `output/pretrained/chronos-2`에 공유 저장하고 각 실험에는 공개 revision 및 파일 SHA256을 보관합니다.
- 실행 엔진에는 기본값이 꺼진 정책 함수를 추가했습니다. 기본 경로의 주문·체결·잔고·판단은 기존 릿지 원본과 완전히 같은지 검사했습니다. 기존 9개 실험의 원본 JSON/HTML은 수정하지 않았습니다. 지갑/API 키나 거래소 주문은 사용하지 않았습니다.

재실행:


완료된 연구 초안은 동일 protocol인지 확인하고 재사용합니다. 같은 이름의 설정을 변경해 덮어쓰지 않습니다. 원자료를 바꾼 새 실험은 별도 protocol/실험 경로로 진행해야 합니다.

### 변경한 계산과 예측

- `v3/engine.py`는 청산이 일부만 체결돼도 잔량 정리 상태를 유지합니다. 완료된 봉으로 판단하고 다음 봉 시가에 비용을 반영해 체결합니다. 체결량 상한은 **직전 완료 봉** 거래량만 사용합니다. 같은 경계의 종가 관측 직후 시가 체결을 가정하므로 실제 통신 지연·호가 대기열을 재현하는 것은 아닙니다.
- GOLD 수량 단위를 0.0001로 적용하고 종목별 수량 단위·최소 주문 금액을 검사합니다. 과거 par 규격을 복원한 것이 아니라 현재 규격을 과거 참조 가격에 적용한 실험입니다. 정확한 과거 par mark/oracle/호가, 증거금·강제청산·OI 제한은 재현하지 않습니다. 과거 펀딩은 여전히 0 가정입니다.
- 일별 변동성은 양쪽 UTC 자정 평가자산이 존재하는 온전한 24시간 수익률의 표본 표준편차입니다. 시작/종료의 부분 일자는 제외합니다. 손익·수수료·보유분 장부를 별도로 대사합니다.
- 예측 목표는 다음 봉 시가 진입부터 4시간 후 시가까지의 **단순 수익률**입니다. 학습·모델 선택·확률/구간 보정을 시간순으로 나누고 미래 구간에 걸친 정답을 제거합니다. 정규화는 학습 구간에만 적합합니다.
- 분류기는 왕복 수수료·슬리피지를 넘겨 2bp 이상 이익인 long/short/대기 사건을 예측합니다. 나중 검증 구간으로 확률을 보정하고 확률 60%와 기대 순이익 기준을 함께 적용합니다. 출력의 비용 손익 점수는 가격 수익률 점예측과 다릅니다. 세 과거 기간 모두 진입이 없어, 유용한 매매 전략으로 입증된 결과가 아닙니다.

- `fixed4h`는 4시간 후 정리 요청, `adaptive`는 최대 8시간·손절 2%·익절 4%·반대 신호·변동성에 따른 수량·계좌 낙폭 제한을 사용합니다. 부분 체결이면 보유 시간이 길어질 수 있고 계좌 2% 중단 기준도 손실 상한을 보장하지 않습니다. 유동성 ¼, 슬리피지 20bp 비교는 예측을 고정한 `adaptive` 규칙입니다.

근거: [Returns from liquidity provision in cryptocurrency markets, JBF 2025](https://pure-oai.bham.ac.uk/ws/portalfiles/portal/264447617/Farag2022Returns.pdf), §2, 식 (1).
과거 수익률 `r_i`에서 동일가중 시장 평균을 뺀 `e_i`에 대해 논문 비중은
`w_i = -2 * e_i / sum(abs(e))`입니다. 상대적 하락 자산을 사고 상승 자산을 팔며,
비중 합은 0, 절대 비중 합은 2입니다. 이 방향과 다음 기간 수익률의 내적이 논문의 반전 수익입니다.
회계 검사는 식을 직접 계산한 값과 일치하는지 확인합니다. 단순 가격비율 페어트레이딩이나
공적분 모형은 아닙니다. 명목금액의 롱·숏 균형은 시장 β 중립을 보장하지 않습니다.

원문은 122종목·5분 자료의 유동성 공급 보상 연구입니다. 여기서는 BTC·ETH·HYPE 시간봉에
적용하므로 논문 전체 재현이나 par 수익성 입증이라고 부르지 않습니다. 모델 기반 진입 필터,
수량 제한, 비용, 회복/손실 청산은 이번 프로젝트의 추가 설계입니다.

  HYPE 2자리 수량과 가격 정밀도 규칙으로 보수적으로 반올림합니다. 용량은 직전 봉 거래량의

### 위험 비중 보완

4차 버전 `3109c29d1498af1a`는 최근 평가 구간에서 기본 순이익 +183.58이었지만,
복합 불리 조건에서는 −795.54였습니다. 거래별 실현손익에서 수수료를 뺀 기여는
BTC +1,153.26, ETH +1,359.43, HYPE −2,384.54였으며 펀딩 합계 +55.43은 별도입니다.
이를 확인한 **후** 5차 위험 비중 확장을 설계했으므로 이 개발을 독립 검증으로 해석하면 안 됩니다.

5차는 같은 반전 가설과 모델/보유/비용 후보를 유지하고, 비중을 제약식이 있는 평균-분산 방향으로
바꿉니다. `r`은 과거 구간 수익률, `Sigma`는 과거 72개 완성된 시간봉 수익률의 공분산
(표본 공분산 80% + 대각 공분산 20%)입니다. `1`은 모든 원소가 1인 벡터입니다.

```text
u = -Sigma^-1 r + Sigma^-1 1 * (1' Sigma^-1 r) / (1' Sigma^-1 1)
w = u / sum(abs(u))
```

이는 `(-r)'w - gamma/2 * w' Sigma w`를 `sum(w)=0` 아래 최대화한 방향을 정규화한 것입니다.
원논문의 단순 반전 가설에 위험 배분을 추가한 설계이며, 개별 종목의 원래 매수/매도 부호가
달라질 수도 있습니다. 공분산이 동일 분산의 대각행렬이면 원래 논문 방향으로 돌아갑니다.
달러 중립과 과거 수익률에 반대인 포트폴리오 성질을 검사했습니다. 공분산 추정이 미래 위험을
보장하지 않으며, 위험 비중 자체가 예측 우위를 만들어내는 것도 아닙니다.
비교표의 `1시간 반전 기본형`은 계속 원래 비중을 사용합니다.

버전별 화면은 `/reversal-study/?study=<identity>`로 고정됩니다. 이전 완결 버전은
`/reversal-study/?study=14efedeeaec3926b`, `/reversal-study/?study=3109c29d1498af1a`이며,
검증만 수행한 앞선 두 버전은 원본 `validation.json`을 보존합니다.
